### Wrong or missing, now fixed in the plan (12)

1. **Brand-neutral rule.** design.md named the sibling repository's product. Now it says "a sibling repository" (AGENTS.md rule 3).
2. **An undeclared variable.** `SHORTS_TOOLCHAIN` appeared only in Risks, and doctor would have reported it as an unknown setting. Removed, with no opt-out: the toolchain step only puts the project's own tools first.
3. **Repeated `PATH` lines.** Whether `$CLAUDE_ENV_FILE` survives `resume` isn't documented. The script now writes its line only once, with a test.
4. **The provider discovery can miss one without a word.** It greps one line per declaration, so a declaration Biome wraps over several lines would escape the sandbox, and the real Keychain key would be used. A guard test now counts the declarations.
5. **Desktop branch names.** They are `claude/<session name>-<suffix>` (your branch prefix is `claude`). The "longest change name contained in it" rule covers that, now with a test.
6. **Detached HEAD.** Two of the sibling repository's three desktop worktrees are detached. The session line now says so and gives `git switch -c <change>`.
7. **The desktop base commit isn't documented,** and `worktree.baseRef` doesn't apply to desktop sessions. The open question says so, and the docs will say to check `git log -1` in a new worktree.
8. **Desktop hooks run in the main checkout,** so `$PWD` is wrong there. The design now relies on the input's `cwd` and says what happens without it: you get the main checkout's line and no install. That's harmless, and unlikely since `jq` ships with macOS.
9. **The count was wrong.** "Six changes build on group 1" is five directly, plus two through them.
10. **Review order.** `/code-review xhigh` now comes before the readability agent, so readability polishes the reviewed code. The PR is opened for your review, and merging stays yours.
11. **Codex was over-promised.** The spec said Codex sessions SHALL get ready, but Codex runs project hooks only once they're trusted. The requirement is now scoped to "when the session-start hook runs".
12. **TOML check overkill.** `taplo` for a three-key TOML file is replaced by running the setup command by hand.

### Found on the way, outside the plan, for you to decide

- **Four `mcp serve` processes are running now** (`pgrep -fl "mcp serve"`). Because the verify skill's `pkill` never matched, some may be leftovers from verify runs rather than live sessions.
- **The verify skill is still uncommitted** (untracked `.agents/skills/verify/`, an AGENTS.md line, one line in each pending `tasks.md`). The plan's task 0.1 waits for it, because this change edits the same files.
- **"Auto-archive sessions when their pull request closes" is off** in your app settings. Turning it on would archive a lane's session after its PR merges. Its worktree stays on disk only if it has uncommitted changes. That's your choice; the plan doesn't depend on it.
