# AGENTS.md

Rules for humans and AI agents working in this repository. Claude Code and Codex both read this file; don't add a `CLAUDE.md`, or Claude Code stops loading this one.

## What this is

A CLI and MCP server that turns audio into vertical short videos: transcript with word timings, beats, one AI image per beat, and an FFmpeg draft with captions. What it does and for whom is in [README.md](README.md); how it's built is in [docs/architecture.md](docs/architecture.md).

## Golden rules

1. **No secrets in git.** Key names live in [.env.example](.env.example); values live in the environment or the macOS Keychain.
2. **No user content in git.** Posts, media, `brand.json` and the ledger live under `SHORTS_POSTS_DIR` / `SHORTS_DATA_DIR`.
3. **Brand-neutral.** No product, client or brand names in code, docs or samples.
4. **One place per fact.** Link instead of repeating; the table below says where each thing lives.
5. **The user decides.** Approving a script or a draft is CLI-only; never approve on the user's behalf.

## Planning with OpenSpec

Read `openspec/` before changing behaviour: `openspec/specs/` is how the system behaves today, `openspec/changes/` is pending work. New behaviour starts as a change (`openspec-propose` skill), and `openspec validate --all --strict` must pass. The CLI is pinned in the Nix shell.

## Effect

The repo uses `effect@4.1.2` (`effect/cli`, `effect/ai`). Check every API against `node_modules/effect/dist/**/*.d.ts` or [docs/vendors/effect](docs/vendors/README.md), never memory. Effect goes at seams (interruption, CLI and MCP surfaces); operations are plain functions over a `Context` object, child processes use `spawn` with `stopWhenAborted`, files use `node:fs`. The reasoning is in [docs/architecture.md](docs/architecture.md#key-decisions).

## Development

```bash
nix develop                 # Node 24, ffmpeg-full, OpenSpec; or direnv with .envrc
pnpm install
bin/shorts-studio config show
pnpm check && pnpm check-types && pnpm test
```

- Tests are plain vitest with `// GIVEN / WHEN / THEN` comments, beside the code they cover in `test/`. Anything needing ffmpeg, the network or a paid API is `*.integration.test.ts` and opt-in (`pnpm test:integration`). Providers are faked: `test/support/fake-fal.ts`.
- A new operation goes in `src/operations/`, is registered in `src/operations/index.ts`, and appears on the CLI and MCP; the parity test checks both.
- Skills: edit `.agents/skills/` only, then `pnpm skills:sync`; the pre-commit hook refuses `.claude/skills/` drifting from it.

## Skills

Repo skills live in `.agents/skills/` (Codex reads them there; `.claude/skills/` is a synced copy for Claude Code). `make-shorts` runs the daily loop and `story-direction` directs a post beat by beat; the `openspec-*` skills are generated by `openspec update`, don't hand-edit them. `commit`, `pr` and `test-bdd` come from the `guillempuche/ai-standards` plugin marketplace: setup per tool is in [docs/getting-started.md](docs/getting-started.md#agents).

## What needs approval

Spending money (`image generate`, later `clip animate`, `audio voice`, `audio music`) asks first: the repo's `.claude/settings.json` marks those MCP tools `ask`. Run spending commands with `--dry-run` first and show the estimate. Never approve a script or a draft, and never raise spending caps without the user saying so.
